# SUNPARK Mini App

Администратор: `/admin → Разработка → Sunpark`.
Приложение обслуживается действующим Python Worker по `/app`. Гостевой Telegram-бот продолжает работать. Новые API пока закрыты для всех, кроме действующих администраторов; ссылка и изменение клиентского режима не обходят проверку прав.

## Дизайн и темы

Реализован выбранный третий вариант: тёмный лесной фон, светлая типографика, оригинальный логотип SUNPARK и растительный декор. Светлая версия сохраняет структуру, использует тёплый светлый фон и зелёные акценты. Приоритет темы — системный `prefers-color-scheme`; если WebView его не предоставляет, используется `Telegram.WebApp.colorScheme`. Изменение темы обрабатывается без перезагрузки. Ручного переключателя нет. Цвета панелей Telegram обновляются вместе с приложением.

## Функции

Актуальная общая главная: четыре направления, небольшой лист и название Sunpark без верхней шапки и блока обращений. Ниже карточек — адрес, маршрут и общие контакты четырёх направлений. Нижняя навигация — «Главная» и «Сообщения». Пустые сообщения содержат действия для бронирования, банкета и вопроса менеджеру; управление видно только администратору. Правила ресторана, мероприятия и закрытие приложения доступны в общих контактах. Подробности и источники — `SERVICES.md`.

После разбора дизайна 15 ноября меню сразу показывает блюда: часть меню выбирается вкладкой, категория — горизонтальной лентой. Поиск работает по всему каталогу. Кнопка «+» добавляет позицию с единственной известной ценой; несколько вариантов требуют явного выбора. «Мой выбор» — сохранённый список для официанта, с количеством и удалением прямо в строке. Его нижняя кнопка появляется только при непустом списке внутри ресторана и меню.

В бронировании календарь открывается по нажатию даты, поэтому выбор времени и продолжение не перекрываются. Дополнительные пожелания свёрнуты, проверка заявки сгруппирована в два редактируемых блока. Подтверждение отправки содержит дату, время и гостей. Возврат восстанавливает исходный раздел даже после вложенных переходов. При вводе сообщения нижняя навигация скрывается, а высота чата учитывает видимую область окна.

- Главная, меню и весь бар из действующего `config.menu`, поиск, состав и обязательный выбор варианта цены.
- «Мой выбор»: одна строка на вариант блюда, кнопки количества, удаление, общая сумма и подтверждение очистки. Сохраняется существующий персональный черновик; отправки заказа в ресторан пока нет.
- Заявки на бронирование и банкеты через существующие анкеты и проверки.
- Собственные обращения и переписка внутри приложения. Фото JPEG/PNG и PDF до 5 МБ; история вложений доступна после проверки прав. Уведомления остаются в Telegram.
- Очередь, принятие заявки, заявки коллег, ответы, быстрые ответы, заметки, завершение, поиск, архив, менеджеры и статистика через действующие бизнес-правила.
- Мероприятия: создание и настройки, лимит самостоятельной записи компании, ручное добавление, список и удаление. Сохраняется временное ограничение мероприятий администраторами.
- Общие контакты четырёх направлений и правила ресторана.

## Адаптация интерфейса — 10 ноября 2026

Product Design применён к уже выбранному оформлению: подготовлены обновлённые визуальные цели бронирования и чата, реализация сопоставлена с ними в `design-qa.md`.

- Заявка на стол: календарь будущих дат, выбор часов и минут прокруткой, гости и контакты, проверка данных перед отправкой. Время указано по Москве; наличие стола подтверждает менеджер. Возврат по шагам сохраняет введённое, персональный черновик можно очистить.
- Банкет: собственная форма, календарь, повод, гости, пожелания и контакты. Свободный вопрос менеджеру доступен отдельно.
- Чат: компактная сводка заявки сверху, сообщения по сторонам диалога, даты, время, PDF и фото, длинная история с подгрузкой. Обновление сохраняет позицию чтения и черновик сообщения. Если пользователь читает историю, новое сообщение не прокручивает её принудительно. Гость может отменить заявку, пока её не взял менеджер.
- Админ-панель: рабочий стол, фильтры новых/своих/чужих/архивных заявок, поиск с поддержкой русского регистра, карточки диалогов, заметки, быстрые ответы и завершение.
- Мероприятия: собственные формы создания/настроек, календарь и время, список участников, запись компании, ручное добавление и удаление с подтверждением. Лимит считается по самостоятельной регистрации; ручное добавление работает сверх лимита.
- Команда: формы добавления и переименования, удаление с подтверждением. Администраторы, закреплённые в настройках размещения, защищены от удаления через интерфейс.

Новые экранные контракты: `screen`, `submit_form`, `command`. Подтверждение Telegram, проверка ролей, защита от повторных запросов и общая база сохранены. Telegram-обработчики остаются совместимыми. Новые таблицы и перенос данных для этой адаптации не нужны.

## Данные и защита

Используются прежние D1-таблицы, заявки и история. Новые таблицы `miniapp_requests` (идемпотентность) и `miniapp_uploads` (временные дескрипторы вложений) создаются автоматически при первой записи через API. Существующие данные и меню не заменяются. Сервер проверяет подпись и срок `initData`, полномочия администратора и доступ к конкретной заявке. В ответах нет токенов Telegram или идентификаторов файлов. Изменения требуют ключ запроса; повтор не выполняет сохранённое действие заново. Отправка сообщения дополнительно проверяет актуальные статус и назначение заявки непосредственно при записи.

При первом входе сохраняется исходная проверка подписи Telegram и предельного возраста `initData` в один час. После неё API выдаёт отдельную сессию приложения на 12 часов: HMAC связывает время выдачи с точными данными запуска, ключ отделён от Telegram HMAC отдельным контекстом. Сессия передаётся в `X-Sunpark-Session`, хранится в памяти и, если доступно, в `sessionStorage` только текущего окна. Перезагрузка не продлевает срок; другой запуск, пользователь, подмена времени или смена токена бота не позволяют использовать эту сессию. Права и владение заявкой проверяются при каждом запросе, включая вложения. База для сессий не добавляется.

По окончании сессии приложение показывает отдельный экран «Сеанс завершён» с инструкцией и закрытием. Ошибка авторизации не подменяется пустым списком сообщений; бесполезный фоновый опрос прекращается. Временный сбой сервера сохраняет повторную попытку.

Вложения загружаются через сервер: Telegram сохраняет файл в служебном сообщении в личном чате отправителя без звука; бот сразу удаляет это сообщение. Если Telegram не разрешит удаление, сообщение может остаться у отправителя. Файл передаётся в диалог только после нажатия «Отправить». Сбой уведомления не отменяет уже сохранённое сообщение.

Статическая оболочка публична, но загрузка каталога и любые пользовательские данные требуют авторизации. API не поддерживает CORS, ограничивает размер запросов и возвращает `no-store`.

## Разработка и проверка

Исходники интерфейса: `ui/app/`. Генерация модуля ресурсов:

```sh
python scripts/build_mini_app_assets.py
PYTHONPATH=src python -m unittest discover -s tests -v
python tests/browser_mini_app_check.py
```

Для браузерной проверки нужны Playwright и Chromium. Она использует локальную SQLite и фиктивный Telegram, не отправляет реальные сообщения. Необязательная проверка Blob/FormData в настоящем Pyodide описана в `tests/runtime_upload_check.cjs`. Сверка с выбранным макетом — `design-qa.md`.

Публикация — обычная сборка существующего Worker из GitHub; параметры размещения и привязка D1 не менялись. Для открытия гостям позднее нужно отдельно изменить `MINIAPP_ADMIN_ONLY` после проверки администраторами. Интеграция с r_keeper отложена.
