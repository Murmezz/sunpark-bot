# Мероприятия SUNPARK

## Временный режим проверки

В src/events.py включён EVENTS_ADMIN_ONLY = True. Раздел скрыт от гостей; /events и ранее отправленные кнопки им недоступны. Текущие администраторы могут открыть пользовательский сценарий через главное меню → «Мероприятия», а управление — через /admin → «Мероприятия». Существующие записи сохраняются. Для публичного запуска переключите EVENTS_ADMIN_ONLY в False и разверните оба модуля обычным способом.

Регистрация встроена в существующий Cloudflare Python Worker. По согласованию с владельцем используется текущее размещение и SQLite-совместимая база Cloudflare D1; миграция на aiogram и отдельный сервер не нужна. Новых Python-зависимостей нет; используется существующий pyproject.toml.

## Для организатора

1. Откройте /admin → «🎟 Мероприятия» → «Создать мероприятие».
2. Введите название, описание (или «—»), будущую дату и время по Москве, место, условия оплаты и лимит гостей самостоятельной записи.
3. Подтвердите данные. Новое мероприятие создаётся с закрытой регистрацией.
4. Проверьте карточку и нажмите «Открыть регистрацию».
5. В «Настройках» можно отдельно изменить каждое поле. Закрытие регистрации не удаляет участников.
6. «Добавить вручную» запрашивает имя и фамилию контактного лица, российский телефон, количество гостей и необязательный Telegram-ник («Пропустить»).
7. «Посмотреть список / удалить запись» показывает контактные данные, размер компании и автора добавления. Удаление требует подтверждения.

Администраторам доступны те же ID, что уже настроены в SUNPARK; авторизация повторяется для кнопок и незавершённых административных форм.

## Для гостя

«🎟 Мероприятия» находится на главном экране; также работает /events. Выберите мероприятие, нажмите «Зарегистрироваться», введите имя, фамилию, российский телефон и общее количество гостей, включая себя. Telegram ID и username сохраняются автоматически. Если username отсутствует, сохраняется пустая строка.

Кнопка «Отправить контакт» принимает собственный контакт пользователя; номер можно ввести текстом. Форматы +7, 8 и десять цифр приводятся к единому +7. Повторный телефон или Telegram ID в одном мероприятии не создаёт вторую компанию. Один человек может посещать разные мероприятия.

Подтверждение сохраняет запись и отвечает «Вы успешно зарегистрированы!». Доступна отмена своей записи с подтверждением. /cancel прерывает незавершённый ввод.

## Лимит и хранение

Лимит считается по сумме гостей самостоятельных записей, а не по количеству контактных лиц. Компания из четырёх человек занимает четыре места. Ручные записи не расходуют этот лимит, доступны даже при закрытой записи и заполненном лимите. В карточке админа видны самостоятельные, ручные и все гости.

Проверка свободных мест и INSERT выполняются одним SQL-запросом. Уникальные ограничения предотвращают дубликаты. Сессии FSM сохраняются в D1 и имеют версию для защиты от повторной обработки.

Таблицы: events, event_registrations, event_sessions. Существующая таблица users хранит Telegram-профили всего бота, поэтому регистрации мероприятий вынесены в event_registrations. Телефоны и списки участников доступны только организаторам.

Меню ресторана в config не изменяется, корзина не возвращается.

## Файлы и проверка

- src/entry.py — существующий Worker и подключение раздела;
- src/events.py — раздел мероприятий и постоянная FSM;
- tests/test_events.py — 17 проверок на SQLite, включая независимые одновременные подключения.

Проверка без сети и реального Telegram:

```bash
python -m unittest discover -s tests -p test_events.py -v
```

Развёртывание — через существующий процесс Python Workers проекта с src/entry.py в качестве точки входа. Обязательно включить src/events.py в модульный пакет. Используются действующие привязки DB, BOT_TOKEN, WEBHOOK_SECRET и список MANAGER_IDS/config.manager_ids. Не запускайте параллельно второй polling-процесс с токеном этого бота.
