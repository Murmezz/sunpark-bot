# Пять вариантов просмотра меню

Для администраторов: /admin → «👁 Просмотр меню». Гостевые кнопки и оформление меню не меняются. Все варианты читают действующий config.menu, включая описания, объёмы и обе цены. Банкетное меню не добавляется в каталог.

1. **Навигатор** — обычное сообщение Telegram, категории, шесть кнопок блюд с ценами на страницу. Состав открывается в том же сообщении.
2. **Меню на листе** — Rich HTML: компактная таблица «блюдо / цена», названия являются callback-кнопками в тексте. Состав выбранного блюда показывается под таблицей.
3. **Раскрывающийся состав** — Rich HTML details/summary: в свёрнутом виде только название и цена, состав раскрывается по нажатию.
4. **Фирменный SUNPARK** — Mini App в стиле печатного меню: оригинальный логотип SUNPARK и растительный рисунок из «Копия Menu_2026.pdf», белая карточка с зелёной рамкой, коричневые заголовки с боковыми линиями, цены справа. Сначала открываются крупные карточки разделов; выбор раздела ведёт на отдельный список блюд с ценами и кнопкой «К разделам меню». Состав открывается по нажатию на блюдо. Исходник задаёт только оформление: названия, составы и цены берутся из актуальной базы бота.
5. **Вечерний SUNPARK** — Mini App с тёмным фоном и золотистыми акцентами, той же структурой разделов, крупными кнопками, поиском и карточкой состава.

Оформление выбирается при запуске из админ-панели. Кнопки «Сменить вид» в Mini App нет. Оба оформления используют общую структуру и размеры элементов: текст блюд 16–17 px, цены 15–16 px, строки от 68 px, кнопки разделов от 88 px. Кнопка Telegram «Назад» сначала закрывает карточку блюда, затем возвращает к разделам. Поиск работает по всему меню. Кнопки «Еда», «Напитки» и «Бар» целиком видны на узком экране; дополнительные части меню переносятся на следующую строку. Эмодзи и оформление исходных заголовков не мешают коротким названиям кнопок. Фотографии блюд не имитируются и не используются. Корзины нет. При отклонении Rich HTML сервером предусмотрен совместимый текст с небольшими номерными кнопками; сетевые ошибки и rate limit не вызывают каскада повторных отправок.

## Доступ

Все callback-кнопки с префиксом mp: требуют актуальных прав менеджера и личного чата. Простое копирование кнопки не даёт доступа.

Mini App отдаёт публично только пустую оболочку HTML/CSS/JS. POST /api/menu-preview проверяет Telegram.WebApp.initData: HMAC-SHA-256, auth_date не старше часа и Telegram ID из подписанного user. После этого проверяется действующий список менеджеров. Переданный отдельно user_id не используется. Гостю с корректной подписью возвращается 403, без подписи — 401. Ответ не содержит config, профили, телефоны или регистрации мероприятий. Размер тела ограничен при чтении потока; ответы не кешируются. Секрет бота не попадает в браузер или URL.

## Файлы

- src/menu_preview.py — формирование вариантов, авторизация и HTTP-маршруты;
- ui/menu_preview/index.html, style.css, app.js — исходники Mini App;
- ui/menu_preview/sunpark-logo.svg — исходные векторные контуры логотипа из PDF;
- ui/menu_preview/botanical-pattern.webp — растительный рисунок из PDF, подготовленный для мобильного фона;
- src/menu_preview_assets.py — те же статические ресурсы в Python-строках для доставки модульным Python Worker;
- tests/test_menu_preview.py — подписи, доступ, пагинация, безопасный вывод и fallback;
- tests/browser_preview_check.py — проверка двух оформлений в Chromium на ширине 320, 390 и 820 px с проверкой навигации, размеров кнопок, читаемости цен, поиска и возврата. Только локальный тест использует фиктивный токен и тестовую подпись, в рабочем боте обхода авторизации нет.

Новых production-зависимостей нет. После изменения HTML/CSS/JS выполните сборку ресурсов. Обычные проверки проекта:

```sh
python scripts/build_menu_preview_assets.py
PYTHONPATH=src python -m unittest discover -s tests -v
node --check ui/menu_preview/app.js
```

Для локальной проверки интерфейса дополнительно нужны Playwright и Chromium:

```sh
python -m pip install playwright
PYTHONPATH=src python tests/browser_preview_check.py
```

Логотип отдаётся по /menu-preview-logo.svg. Растительный фон упакован сборщиком в CSS как data URL, без внешних сервисов и загрузки полного PDF. Фирменные элементы используются только в варианте 4; вариант 5 сохраняет вечернее оформление.

В модуль Worker должны входить entry.py, events.py, validation.py, menu_preview.py и menu_preview_assets.py вместе с существующим SDK. Действующие настройки, привязки, база и секреты сохраняются. Публикация выбора варианта для гостей не производится.
